# 치이카와 코인 대모험

브라우저에서 즐기는 2D 자동 달리기 게임 프로토타입입니다.

## 실행

`dist/index.html`을 브라우저에서 열거나, Node.js 설치 후 다음 명령을 실행합니다.

```sh
node server.cjs
```

http://127.0.0.1:4173 에 접속합니다. 외부 패키지 설치는 필요 없습니다.

## 2인 방 코드 경쟁 (로컬 프로토타입)

`node server.cjs`로 실행해야 합니다. 파일을 직접 여는 방식에서는 대전 API를 사용할 수 없습니다.

1. 브라우저 탭 두 개에서 http://127.0.0.1:4173 에 접속합니다.
2. 첫 탭에서 닉네임을 정하고 **방 만들기**를 누릅니다.
3. 두 번째 탭에서 다른 닉네임과 6자리 방 코드를 입력해 **입장**합니다.
4. 방장이 **둘이 함께 시작**을 누르면 공통 3초 카운트다운 후 시작합니다.
5. 점프는 각자 조작합니다. 공통 코스와 실시간 점수, 서로 다른 캐릭터 2개를 선명하게 표시합니다. 방장은 치이카와, 입장한 친구는 파란 귀 캐릭터입니다.
6. 둘 다 종료되거나 제한 시간이 지나면 점수로 승패를 집계합니다. 재대전은 나가기 후 새 방을 만듭니다.

대전에서는 일시정지가 없고, 피버 중에도 코스 이동 속도를 동일하게 유지합니다. 피버 무적·자동수집과 연출은 유지됩니다. 멀티 기록은 싱글 개인 랭킹에 등록하지 않습니다.

서버는 메모리에 방을 보관하므로 서버 재시작 시 방이 사라집니다. HTTP 폴링 기반이며, 점수는 클라이언트가 계산하는 로컬 테스트용입니다. 공개 서비스에 필요한 서버 판정·인증·부정행위 방지는 구현하지 않았습니다. 기본 서버는 localhost에만 열립니다. 같은 와이파이 공유는 아래 설정을 사용합니다.

멀티 API 검사: `node test-rooms.cjs` / 두 캐릭터 검사: `node test-duo.cjs`

각자 점프·2단 점프하며 상대 화면에 위치와 포즈를 전송합니다. 두 화면에서 1P와 2P 위치는 동일합니다. 한 명이 탈락해도 상대 플레이를 관전할 수 있습니다.

### 같은 와이파이의 다른 기기에서 접속

PowerShell에서 다음과 같이 실행합니다.

```powershell
$env:GAME_HOST="0.0.0.0"
node server.cjs
```

서버를 실행한 컴퓨터에서 `ipconfig`로 Wi-Fi IPv4 주소를 확인하고 친구에게 `http://<내부-IP>:4173`을 전달합니다. 친구에게 127.0.0.1 링크를 보내면 친구 자신의 컴퓨터를 가리킵니다.

Windows 방화벽은 사용하는 Node 실행 파일의 TCP 4173 포트를 같은 로컬 서브넷에서만 허용해야 합니다. 기존 Node 차단 규칙이 있으면 허용 규칙보다 우선할 수 있습니다. Codex 격리 계정으로 실행할 때 외부 접속이 차단될 수 있어, 이번 검증에서는 일반 사용자 환경에서 서버를 실행했습니다. 방화벽 변경 자체는 저장소 코드에 포함되지 않습니다.

서버가 꺼지거나 Wi-Fi IP가 바뀌면 기존 링크가 동작하지 않습니다. 친구가 같은 방 코드로 입장해야 함께 플레이합니다.

## 싱글 조작과 규칙

- 스페이스바 / 위쪽 화살표 / 화면 터치: 점프. 공중에서 한 번 더 누르면 2단 점프.
- P 또는 화면 버튼: 일시정지.
- 체력 3개로 시작하며, 30초씩 총 4개 스테이지를 통과하면 클리어합니다.
- 일반 코인 10점, 별 코인 100점, 무지개 코인 300점과 5초 피버.
- 피버 중 공중 고속 비행, 무적, 코인 자동 수집.
- 보호막: 한 번 방어 / 자석: 7초 자동 수집 / 하트: 체력 1 회복.
- 20콤보마다 점수 배율 상승, 최대 3배. 스테이지 전환 500점, 최종 클리어 2,000점.
- 최고 점수는 브라우저 로컬 저장소에 저장합니다.

## 검증

```sh
node test-game.cjs
node test-rooms.cjs
node test-duo.cjs
```

점프 제한, 화면 경계, 피버 충돌 보호, 아이템, 체력, 콤보, 스테이지 전환, 일시정지, 클리어와 재시작의 자동 회귀 검사를 실행합니다.
캐릭터 포즈 선택·발 위치 정렬·이미지 로드 실패 대체, 아이템이 장애물 안에 생성되지 않는지, 스테이지별 최악 패턴이 점프로 통과 가능한지도 검사합니다. 렌더링은 모의 객체이므로 실제 화면 확인은 브라우저에서 따로 해야 합니다.

## 에셋

캐릭터 이미지는 내장 이미지 생성 도구로 만든 비공식 팬 게임용 에셋입니다. 생성 프롬프트는 `sprite-prompt.txt`, 두 번째 캐릭터 프롬프트는 `friend-sprite-prompt.txt`에 있습니다. 치이카와 캐릭터에 관한 권리는 원권리자에게 있으며, 공식 제휴 프로젝트가 아닙니다.


## Claude Code CLI 연결 및 협업 (2026-11-17)

Claude 앱 로그인과 Claude Code CLI 로그인은 별도입니다. 이 프로젝트에서는 CLI를 설치하고 프로젝트 폴더에서 인증을 확인한 다음, 캐릭터·오브젝트 개선 작업을 실제로 전달했습니다. 이후 멀티플레이·랭킹·네트워크 수정은 Codex가 수행했습니다.

### Windows 설치와 프로젝트 연결

공식 설치 안내: https://code.claude.com/docs/en/setup

```powershell
irm https://claude.ai/install.ps1 | iex
```

설치 후 새 PowerShell에서 프로젝트 폴더로 이동합니다.

```powershell
cd "<이 저장소를 내려받은 폴더>"
claude --version
claude auth login
claude auth status
claude
```

`auth status`에서 `loggedIn: true`인지 확인합니다. Claude 앱에만 로그인되어 있어도 CLI는 미인증일 수 있습니다. 인증 코드가 필요한 경우 터미널에 입력하고 저장소나 채팅에 게시하지 않습니다.

Windows에서는 `start-claude.cmd`를 실행해도 이 프로젝트 폴더에서 CLI가 열립니다. 사용자 기본 설치 위치인 `%USERPROFILE%\.local\bin\claude.exe`를 우선 사용하므로 PATH가 아직 갱신되지 않은 경우에도 실행할 수 있습니다.

### 함께 저장한 연결 파일

- `CLAUDE.md`: Claude가 읽는 구조·실행·테스트·기존 규칙·작업 범위 안내.
- `start-claude.cmd`: 현재 프로젝트 폴더에서 Claude CLI를 여는 Windows 실행 파일.
- `claude-task.txt`: 실제로 전달한 캐릭터·오브젝트 개선 요청. 새 세션에도 재사용할 수 있습니다.

CLI를 열고 먼저 다음처럼 요청합니다.

> CLAUDE.md와 README.md를 읽고 현재 구조를 설명해줘. 파일을 수정하기 전에 개선 계획을 알려줘.

실제 작업에서는 Claude에 코드 읽기·파일 수정·Node 테스트를 허용했습니다. Windows에서는 PowerShell 테스트 명령 승인을 Bash 명령과 별도로 처리해야 했습니다. 사용자 승인 검사를 전체 해제하는 옵션은 사용하지 않았습니다. 여러 도구가 같은 파일을 동시에 수정하지 않도록 작업을 순차 진행했습니다.

### 실제 수행한 개선

Claude는 스프라이트 경계를 분석해 포즈별 발 위치를 보정하고, 달리기·점프·착지·피격·피버 애니메이션, 코인 회전·아이템 획득 효과, 장애물 예고와 회귀 테스트를 개선했습니다. 완료 후 Codex가 테스트를 재실행하고 브라우저 화면도 확인했습니다.

당시 CLI 버전은 **2.1.326**, 세션 기록의 모델 식별자는 **claude-opus-5-5**였습니다. 세션 기록 집계: 일반 입력 44토큰, 캐시 생성 입력 94,211토큰, 캐시 재사용 입력 1,471,780토큰, 출력 56,936토큰. 캐시 재사용은 이전 컨텍스트의 반복 읽기를 포함하며, 이 수치로 실제 청구액이나 계정 잔여 한도를 판단할 수 없습니다.

계정 인증 파일·토큰·이메일·CLI 원본 세션 로그는 업로드하지 않습니다. 다른 사람이 이 저장소를 내려받으면 본인 Claude 계정으로 별도 로그인해야 합니다.
